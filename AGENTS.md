# Product Design Psychology — Core Design System

Use https://productdesignpsychology.com/ as a reference for product and interface decisions.

Do NOT copy its visual style.
Do NOT blindly apply psychological principles.
Extract the underlying principles and apply them only when they improve the user's actual experience.

---

## 1. Design for the User, Not the Designer

Never assume the user thinks like the developer.

Before making a UX decision, ask:
- Is this based on evidence?
- Or does it simply feel obvious to me?
- Would a first-time user understand this without explanation?
- Am I designing for myself?

Treat designer intuition as a hypothesis, not evidence.

---

## 2. Solve the Real Problem

Before implementing a requested feature:
1. Identify the actual user problem.
2. Question the framing of the problem.
3. Consider alternative explanations.
4. Identify the desired user outcome.
5. Only then design the solution.

Do not solve the wrong problem beautifully.

---

## 3. First Impression Matters

Users form an emotional reaction before fully understanding the interface.

Therefore:
- Evaluate the first screen.
- Evaluate the first interaction.
- Evaluate the first moment of confusion.
- Evaluate the first moment of trust.
- Remove anything that creates unnecessary anxiety or uncertainty.

The first impression should not require explanation.

---

## 4. Minimize Cognitive Load

Do not make users think unnecessarily.

Prefer:
- Fewer choices
- Clear hierarchy
- Obvious actions
- Familiar interaction patterns
- Progressive disclosure
- Short, concise copy
- Meaningful defaults
- Predictable navigation

Never add complexity merely because the feature exists.

---

## 5. Choices

Every additional choice has a cost.

Before adding buttons, tabs, filters, settings, plans, options, or menus, ask:
> "Does the user actually need to make this decision?"

If not, make the decision for them when it is safe and reversible.

---

## 6. Defaults

Every default is a design decision.

For every default state ask:
- What happens if the user does nothing?
- Does this outcome benefit the user?
- Is it reversible?
- Is it genuinely the most useful default?

Never use psychological principles to manipulate users against their interests.

---

## 7. Make Interaction Obvious

Do not hide clickable elements merely to make the UI look minimal.

Users should understand:
- What is clickable
- What is editable
- What is selected
- What happens next
- Whether an action succeeded

Visual elegance must never destroy usability.

---

## 8. Respect Familiar Patterns

Do not redesign interaction patterns just to appear innovative.

If a familiar pattern works: **use it**.

Innovation should solve a real problem, not force users to relearn basic interactions.

---

## 9. Habits Matter

Users bring existing habits from other products.

Do not assume users will abandon familiar behavior simply because our design is theoretically better.

When introducing a new interaction:
- Explain it when necessary
- Provide familiar alternatives when possible
- Minimize learning cost

---

## 10. Users' Words Are Not Always Behavior

Treat stated preferences as evidence, not truth.

When possible, prioritize:
$$\text{Actual Behavior} > \text{Observed Friction} > \text{Repeated Behavior} > \text{Stated Preference}$$

Do not build an important feature solely because users say they want it.

---

## 11. Emotional Reaction

Before asking what users "think", evaluate what they "feel".

Ask:
- Does this feel trustworthy?
- Does it feel confusing?
- Does it feel overwhelming?
- Does it feel slow?
- Does it feel rewarding?
- Does it feel safe?

Fix negative emotional reactions before optimizing secondary details.

---

## 12. Progress

Real progress can motivate users.

Use progress indicators when they represent genuine progress.
Never create fake progress simply to manipulate completion.

---

## 13. Last Moment

Design the final moment of every important flow deliberately.

Ask:
> "What should the user feel immediately after completing this?"

Success should feel: **clear + rewarding + complete**.

---

## 14. Cultural Awareness

Never assume a design convention is universal.

Consider:
- Language
- Culture
- Symbols
- Colors
- Reading direction
- Expectations
- Local conventions

Design for the actual audience.

---

## 15. Avoid Feature Creep

A product does not become better because it has more features.

Every proposed feature must answer:
1. What user problem does this solve?
2. How frequently does that problem occur?
3. Why does it belong in this product?
4. What complexity does it introduce?
5. Can the existing product solve it more simply?

If the answer is weak: **do not build it**.

---

## 16. Metrics Are Not the User

Never optimize a metric blindly.

A higher click-through rate, conversion rate, session length, or retention number does not automatically mean a better user experience.

Ask what happened to the actual user.

---

## 17. Ethical Psychology

Psychology must improve the user's experience.

Never use:
- Deceptive defaults
- Hidden cancellation
- Artificial urgency
- Fake scarcity
- Misleading progress
- Dark patterns
- Confusing opt-outs

Use persuasion to help users accomplish their goals, not to trap them into actions they would not freely choose.

---

## 18. Design Review Checklist

Before considering any feature or interface complete, evaluate:

### User
- Who is this for?
- What are they trying to accomplish?
- What do they already know?
- What habits do they bring?

### Psychology
- What assumptions are we making?
- What cognitive load are we creating?
- What choices are we forcing?
- What emotional reaction might occur?

### Interface
- Is the primary action obvious?
- Is the hierarchy clear?
- Are familiar patterns being respected?
- Are important states visible?

### Product
- Does this solve the actual problem?
- Is this feature necessary?
- Is there a simpler solution?

### Ethics
- Does this help the user?
- Is anything manipulative?
- Would we be comfortable explaining this design publicly?

---

## Core Principle

> Build the simplest product that helps the user achieve the desired outcome with the least unnecessary mental effort.

- When simplicity conflicts with feature quantity: **choose simplicity**.
- When designer preference conflicts with user evidence: **choose evidence**.
- When engagement conflicts with user benefit: **choose user benefit**.
